# Задания для студентов

Три самостоятельных файла — три алгоритма поиска. В каждом файле нужно
реализовать функцию (или две), помеченные `TODO`, — они стоят в самом начале
файла, сразу после подключений. Всё остальное (разбор параметров, генерация
данных, замер времени) уже готово и менять его не нужно.

| Файл         | Что реализовывать                        |
|--------------|------------------------------------------|
| `linear.cpp` | `find_linear` — поиск перебором          |
| `buckets.cpp`| `build_buckets` и `find_in_buckets`      |
| `binary.cpp` | `find_binary` (сортировка уже готова)    |

## Компиляция и запуск

Каждый файл собирается отдельно, одной командой. Для `linear.cpp`:

```
g++ -std=c++17 -O2 -o linear linear.cpp
./linear
```

Точная команда для каждого файла продублирована в его шапке. На Windows
нужен MinGW-w64 (команда та же, только `g++` из его комплекта) или WSL.

Пока `TODO` не заполнен, программа честно компилируется, но при запуске
сообщает: `Ошибка: ...: функция не реализована (см. TODO)`.

## Параметры запуска

Все значения по умолчанию подходят для первого запуска, параметры нужны для
экспериментов:

```
./linear --size 1000000 --queries 1000 --seed 42 --hit-rate 0.5
```

- `--size N` — сколько случайных ID в базе;
- `--queries M` — сколько запросов в батче (время в выводе — среднее на один запрос);
- `--seed S` — зерно генератора: один и тот же seed = один и тот же тест;
- `--hit-rate P` — доля запросов, присутствующих в базе (ровно floor(M·P)).

## Как понять, что реализация корректна

- программа должна находить ровно 500 из 1000 запросов при дефолтных
  `--queries 1000 --hit-rate 0.5` — счётчик «Найдено» в конце вывода;
- на одном и том же seed и одинаковых параметрах все алгоритмы и все
  варианты в команде обязаны дать одинаковый «Найдено» — сверяйтесь друг с
  другом через `--seed`;
- граничные режимы: `--hit-rate 0` (ничего нет в базе) и `--hit-rate 1`
  (все запросы из базы).

## О времени

Не ставьте большое `--queries` для `linear`: перебор по базе из миллиона ID
ищет сотни микросекунд на запрос, батч из 100000 будет идти около минуты.
Это, кстати, и есть предмет семинара — сравните то же время с
`buckets`/`binary` при одном seed.
